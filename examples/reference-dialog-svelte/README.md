# 참고용 동기화 대화상자 (Svelte)

md-works 의 `SyncDialog.svelte` 와 `state.svelte.ts` 를 원본 그대로 복사한 것이다. 타입 검사와 테스트 대상이 아니다.

md-works 의 UI 인프라(modal, motion, tooltip)에 의존하므로 그대로 동작하지 않는다. 화면 구성·문구·상태별 처리를 참고하라. 프레임워크 없이 쓸 상태 로직은 `../headless-state/` 에 있다.

| 파일 | 내용 |
|---|---|
| `SyncDialog.svelte` | 대화상자. 상태 줄, 연결 폼, 키 표시·복사, 사용량, 문제 안내 카드, 연결 해제 |
| `state.svelte.ts` | 룬(`$state`)으로 만든 상태·설정 저장·엔진 연결. `../headless-state/controller.ts` 가 이것을 룬 없이 다시 쓴 것이다 |

## 화면 구성

1. 상태 줄: 현재 상태, 마지막 동기화 시각, 지금 동기화 버튼
2. 연결 전: Worker 주소, 연결 방법(이 기기에서 새로 시작 / 다른 기기의 키로 연결), 초대 코드 또는 동기화 키
3. 연결 후: 문제 안내 카드(해당할 때만) → 동기화 키(가림·보기·복사) → 사용량 → 동기화되는 것 → 연결 해제
4. 입력 오류는 해당 칸 옆에, 작업 결과 오류는 상단 고정 영역(`role="alert"`)에 보인다
5. 되돌릴 수 없는 동작(연결 해제, 이 기기에서 지우기, 삭제 반영)은 확인 단계를 한 번 거치고 처음 포커스를 취소에 둔다

## 상태 줄 문구

문구는 `core/src/syncLabels.ts` 의 `phaseLabel` 이 만든다.

| 상태(`phase`) | 문구 |
|---|---|
| `off` | 동기화를 쓰지 않는 중 |
| `idle` | 최신 상태입니다 |
| `pending` | 올릴 변경을 기다리는 중… |
| `syncing` | 동기화하는 중… |
| `offline` | 오프라인입니다 — 연결되면 이어서 동기화합니다 |
| `error` | 동기화하지 못했습니다: (문제 제목) |
| `paused` | 멈춤: (문제 제목). 문제가 없으면 `멈춤` |

## 문제 안내 카드

제목은 `problemTitle` 이 만들고, 본문은 `SyncDialog.svelte` 가 문제 종류(`lastError.kind`)별로 고른다.

| 종류 | 제목 | 본문 요지 | 버튼 |
|---|---|---|---|
| `unauthorized` | 키를 확인하세요 | 서버가 이 키를 받아 주지 않는다. 키를 잘못 입력했거나 다른 공간의 키다. 동기화는 멈췄다 | 키 다시 입력 |
| `forbidden` | 서버가 이 기기를 받아 주지 않습니다 | 초대 코드가 틀렸거나, 허용되지 않은 앱이거나, 서버의 공간 수 한도를 넘었다. Worker 설정을 확인한다 | 다시 시도 |
| `rate-limited` | 오늘의 쓰기 한도에 도달했습니다 | 하루 쓰기 한도에 도달했다. 재시도 시각(다음 00:00 UTC) 이후 자동으로 이어진다. 그동안 항목은 이 기기에 남는다 | 없음 |
| `unavailable` | 서버가 잠시 응답하지 않습니다 | 재시도 시각을 보이고 자동으로 다시 시도한다. 재시도 시각이 없으면 지금 동기화로 다시 시도하게 한다 | 다시 시도 |
| `crypto` | 키가 맞지 않는 데이터가 있습니다 | 받은 데이터를 이 키로 풀 수 없다. 다른 기기와 키가 다르거나 데이터가 손상됐다 | 키 다시 입력 |
| `space-full`, `item-limit`, `item-too-large` | 서버 저장 공간이 가득 찼습니다 / 항목 수 한도에 도달했습니다 / 너무 큰 글이 있습니다 | 서버 한도(항목 수, 전체 용량, 항목 하나의 크기) 때문에 올리지 못한 항목이 있다. 쓰지 않는 항목을 지우거나 줄인다 | 없음 |
| `network` | 서버에 연결하지 못했습니다 | 인터넷 연결을 확인한다. 연결되면 자동으로 이어진다 | 다시 시도 |
| `mass-delete` | 대량 삭제를 확인해야 합니다 | 별도 카드(아래)로 보인다 | 아래 참조 |

카드 맨 아래에 엔진이 준 `message` 를 작은 글씨로 덧붙인다.

## 사용자 결정을 기다리는 카드

| 카드 | 조건 | 안내 | 선택지 |
|---|---|---|---|
| 서버에 없는 항목이 N개 있습니다 | `status.resync` 가 있다 | 이 기기에서 오랫동안 동기화하지 않아 서버가 삭제 기록을 정리했다. 서버에 없는데 이 기기에 남은 항목을 종류·이름으로 나열한다 | `서버에 올리기`(`resolveResync('upload')`) / `이 기기에서 지우기…`(확인 뒤 `resolveResync('delete')`. 되돌릴 수 없음) |
| 항목이 한꺼번에 사라졌습니다 | `status.massDelete` 가 있다 | 전체 N개 중 M개가 사라진 것으로 보여 동기화를 멈췄다. 저장소를 읽지 못했거나 실제로 많이 지운 경우다 | `서버 사본으로 되돌리기`(`resolveMassDelete('restore')`) / `삭제를 서버에도 반영…`(확인 뒤 `resolveMassDelete('proceed')`. 다른 기기에서도 지워지며 되돌릴 수 없음) |
| 동기화되지 않는 글 N개 | `status.oversize` 가 비어 있지 않다 | 항목 하나가 크기 한도를 넘었다. 이름과 크기를 나열한다. 줄이면 자동으로 올라간다 | 없음 |

## 사용량과 안내

| 칸 | 값 |
|---|---|
| 항목 수 | `usage.items` / `LIMITS.MAX_ITEMS_PER_SPACE` |
| 저장 용량 | `usage.bytes` / `LIMITS.MAX_SPACE_BYTES` |
| 오늘 쓰기 | `usage.dailyWrites` / `LIMITS.MAX_DAILY_WRITES` |

비율이 0.8 이상이면 `isNearLimit` 가 참이다. `status.throttled` 가 참이면 "오늘 쓰기 한도의 80% 에 가까워 올리는 간격을 5분으로 늘렸습니다." 를 보인다.

## 연결 흐름의 세부

- `새로 시작`: `clearSyncMeta()` 로 이전 공간의 커서·rev 를 지운 뒤 `connectNew` 를 부르고, 만든 키를 한 번 보여 주며 보관을 안내한다. 서버는 키를 모르므로 잃으면 복구할 수 없다고 적는다.
- `연결`(다른 기기의 키): 키 입력은 `groupKeyInput` 으로 4자씩 끊어 보인다. 공백·소문자는 자동으로 정리된다.
- 키 복사: `navigator.clipboard` 를 못 쓰면 키를 펼쳐 보이고 선택해 직접 복사하게 한다.
- 연결 해제: 이 기기의 키와 설정만 지운다. 항목은 남고 서버와 다른 기기의 데이터는 그대로다. 해제 뒤 `clearSyncMeta()` 로 메타를 지운다.
